# **Open-Source Generative AI for Robotics CAD Modeling: Architectures, Paradigms, and Technical Evaluation**

Computer-Aided Design (CAD) forms the structural foundation of mechanical engineering, industrial design, and physical robotics development1. Historically, three-dimensional generative artificial intelligence focused primarily on visual representations, such as unconstrained triangle meshes (e.g., STL, OBJ formats) or volumetric neural fields (e.g., NeRFs and 3D Gaussian Splatting)1. While effective for virtual graphics and digital rendering, these visual spatial representations lack parametric constraints, exact dimensions, topological validity, and underlying Boundary Representation (B-Rep) structures required for manufacturing, physical stress analysis, and physics-driven robotic simulation1.  
In recent years, the open-source artificial intelligence community and academic research institutions have driven a paradigm shift toward generative frameworks that directly synthesize solid geometry, parametric construction sequences, or executable CAD code5. Within robotics, this evolution extends beyond static single-part generation toward articulated mechanical assemblies, complete with kinematic trees, joint constraints, inertial properties, and Universal Robot Description Format (URDF) export capabilities3.

## **Architectural Paradigms in Generative CAD**

Generative models for CAD modeling can be categorized into three distinct architectural paradigms based on their underlying geometric representation and synthesis mechanism: direct Boundary Representation neural synthesis, parametric sequence and primitive synthesis, and programmatic or agentic CAD code generation5.  
Direct Boundary Representation synthesis models directly generate B-Rep topology—comprising vertices, edges, faces, and loops—alongside underlying geometric curves and surfaces, such as B-splines, planar patches, or cylindrical surfaces5. Rather than predicting sequential construction commands, direct B-Rep synthesis structures geometric data through a hierarchical top-down tree decomposition5. At the root of this hierarchy sits the global solid model, representing the macro-level spatial bounding volume5. Child nodes extending from the root encode localized face geometry parameterized via two-dimensional UV grid surfaces5. These face patches are bounded by child edge nodes that define trimming curves, which ultimately terminate at leaf nodes containing explicit three-dimensional vertex coordinates5.  
Parametric sequence and primitive synthesis models treat CAD modeling as a language translation problem10. Trained on discrete CAD operation command sequences—such as two-dimensional sketch primitives, extrusions, revolutions, and fillets—these systems reproduce the step-by-step design histories typical of human engineers working in commercial parametric CAD software10.  
Programmatic and agentic CAD code generation (often termed CAD-as-Code) relies on Large Language Models (LLMs) and Vision-Language Models (VLMs) fine-tuned or agentically orchestrated to write executable scripts in languages like CadQuery, Build123d, OpenSCAD, or FreeCAD Python4. The programmatic CAD generation workflow functions as an iterative, feedback-driven execution loop8. The pipeline initiates when a multimodal VLM or LLM receives a natural language prompt or reference image, synthesizing this input into executable code written for domain-specific libraries7. This script is dispatched to a sandboxed execution harness running a headless geometric kernel like OpenCASCADE7. If the kernel encounters syntax errors or invalid topological operations, the resulting error stack trace and partial renders are fed back to the language engine for automated repair8. Upon successful compilation, the kernel outputs boundary-representation geometry in industry-standard STEP or STL formats7.

## **Direct B-Rep Diffusion and Neural Synthesis Models**

Direct B-Rep models bypass step-by-step feature sequences and generate complete 3D solid geometry directly in boundary representation format, ensuring direct export to neutral engineering CAD formats, such as STEP and IGES, with fully editable surfaces and topological connectivity5.  
BrepGen represents a significant milestone in direct solid geometry generation5. Introduced by Xu et al., BrepGen utilizes a latent diffusion model that operates on a structured latent geometry representation organized as a hierarchical tree5. The root node corresponds to the complete solid, while lower-level child nodes represent individual faces, bounding edges, and 3D vertices5. Surface geometry is captured by sampling UV grids over parametric domain patches, which are subsequently compressed into geometry latent vectors using dual Variational Autoencoders (VAEs) specialized for faces and edges5. Shared topology between adjacent faces is implicitly encoded through node duplication5. For instance, when two faces share a boundary curve, the edge entity appears twice in the tree5. A transformer-based latent diffusion process progressively denoises node features from root to leaves5. During post-processing, duplicated nodes are detected and merged to re-establish adjacency graphs, closed edge loops trim parent surfaces, and the OpenCASCADE kernel sews the trimmed patches into a watertight B-Rep solid5. BrepGen natively supports free-form, doubly-curved surfaces that traditional sketch-and-extrude models cannot express, while also natively performing CAD autocompletion and shape interpolation tasks5.  
While BrepGen advances direct geometry synthesis, unconstrained diffusion processes can occasionally produce topological invalidities or open boundaries11. DTGBrepGen addresses this limitation by explicitly decoupling topology generation from geometric fitting12. DTGBrepGen generates a topologically valid face-edge-vertex adjacency matrix using an autoregressive graph generation model12. Once topological validity is mathematically guaranteed, a secondary geometry generation network fits parametric surfaces and B-spline curves onto the established topological framework12. This structural decoupling achieves higher validity rates and geometric accuracy compared to end-to-end diffusion models, drastically reducing non-manifold geometric errors on benchmarks like DeepCAD12.

## **Parametric Sequence and Primitive-Based Generative Models**

Parametric sequence models convert geometric modeling histories into discrete tokens, allowing autoregressive transformers to model the sequence of construction operations10.  
DeepCAD pioneered sequence-based deep generative learning for CAD by parsing construction trees into vector sequences representing two-dimensional sketch primitives (lines, arcs, circles) and three-dimensional extrusion parameters14. However, monolithic sequence models often suffer from cumulative error propagation across long sequences10. SkexGen resolves this issue by introducing disentangled discrete codebooks15. Using Vector Quantized Variational Autoencoders (VQ-VAEs), SkexGen factorizes CAD construction into three independent latent codebooks: a topology codebook encoding the structural layout and primitive loop connections of 2D sketches, a geometry codebook encoding exact dimensions, vertex positions, and curvature values, and an extrusion codebook encoding 3D transformation, extrusion depth, and Boolean operations15. Autoregressive decoders sample from these codebooks, enabling targeted user adjustments, such as modifying geometric dimensions while preserving the underlying structural topology15.  
HNC-CAD expands upon disentangled codebooks by organizing CAD shapes into a three-level hierarchical code tree ranging from global assembly arrangement down to local curve details13. Seeking to bring parametric sequence modeling closer to real-world industrial demands, Seek-CAD shifts away from small-scale sketch-extrude datasets10. Built around the SSR (Sketch-Sweep-Revolve) paradigm, Seek-CAD extends command vocabularies to include advanced features such as filleting, chamfering, and shelling10. Seek-CAD employs locally deployed reasoning models (such as DeepSeek-R1) guided by system prompt knowledge constraints and a step-wise visual feedback loop with Chain-of-Thought (CoT) reasoning to iteratively refine generated parametric modeling code without requiring expensive model retraining10.

## **Programmatic CAD and Vision-Language Code Generation**

Programmatic CAD relies on LLMs and VLMs writing code in open-source CAD frameworks, such as CadQuery, Build123d, OpenSCAD, and FreeCAD Python4. Executing generated code inside deterministic CAD kernels guarantees mathematically precise geometry and valid boundary topology16.  
CAD-Coder is an open-source Vision-Language Model developed by Doris et al. to translate image prompts directly into executable CadQuery Python code7. Built on a LLaVA-1.5 multimodal backbone, CAD-Coder utilizes a two-stage training strategy7. Stage 1 aligns visual features with CAD language structures, and Stage 2 performs end-to-end fine-tuning on the GenCAD-Code dataset, which contains over 163,000 paired image and CadQuery Python scripts7. The framework segregates script inference from geometry evaluation7. A dedicated execution environment parses generated scripts through CadQuery, exports STEP files, samples point clouds from rendered solids, and evaluates 3D Intersection-over-Union (IoU) metrics against reference geometry7.  
Build123d serves as a modern, type-safe Python CAD framework built on the OpenCASCADE kernel4. Designed as a successor to CadQuery, Build123d eliminates hidden state dependencies and provides explicit 1D, 2D, and 3D geometry classes with operator-driven modeling, such as algebraic combinations using standard Python operators17. Open-source AI agent harnesses (such as text-to-cad and CADAM) utilize Build123d as an execution backend, providing LLM agents with clear syntax error reporting and structured geometry inspection mechanisms4.  
Addressing freeform surface modeling, NURBGen fine-tunes a Qwen3-4B backbone using LoRA adapters to output mathematical Non-Uniform Rational B-Splines (NURBS) surface parameters directly from text prompts4. This approach bypasses constructive solid primitives to produce organic shapes that export directly to STEP format4.  
In conversational and agentic workflows, systems like openAI-to-freeCAD-workflow integrate conversational LLMs with headless CAD software16. Using Retrieval-Augmented Generation (RAG) backed by vector stores containing verified code snippets, the pipeline generates FreeCAD Python scripts16. A headless execution instance (freecadcmd) executes the script in a sandboxed subprocess16. If execution fails, stdout error traces are fed back to the language model for automated code repair, ensuring the output generates a valid 3D STL or STEP file16.

## **Robotics-Specific Synthesis: Kinematics, Articulation, and Physics Simulation**

Generating individual rigid CAD components is insufficient for physical robotics applications8. Mobile manipulators, quadrupeds, end-effectors, and humanoid sub-assemblies require articulated structures, defined kinematic joints, center-of-mass specifications, and inertial matrices suitable for physical simulation engines like NVIDIA Isaac Sim8.  
The architecture for generating robotics simulation assets operates through a multi-tier agentic pipeline8. A high-level generative layer decomposes natural language or visual requests into semantic kinematic sub-components8. This feeds into a kinematic tree builder that establishes joint limits, motion axes, spatial assembly constraints, and automated mass-inertia tensors derived from solid volume integrals8. The system passes these specifications to an execution layer where sandboxed FreeCAD or OpenCASCADE kernels construct individual rigid geometry files and compile them alongside joint definitions into a Universal Robot Description Format (URDF) file8. Finally, this articulated asset is imported into physics environments such as NVIDIA Isaac Sim and Isaac Lab, enabling reinforcement learning algorithms to train dynamic control policies3.  
ArtiCAD is a training-free multi-agent framework designed to construct editable, articulated CAD assemblies from natural language and visual inputs8. ArtiCAD models articulated mechanisms as a kinematic tree structure comprising parametric parts connected by typed joints (such as revolute, prismatic, or cylindrical) rooted at a fixed base part8. Within ArtiCAD, a Planning Agent decomposes user requirements into a kinematic tree structure, mapping joint types and motion limits8. Parallel Generation Agents write local FreeCAD Python scripts to construct geometry for each component, while dynamic connector contracts position joint frames relative to locally generated geometry8. An Assembly Agent integrates generated parts, computes spatial transformation matrices, checks for spatial interferences, and compiles the final assembly into a valid URDF file for simulation8.  
Articraft provides an agentic environment and domain-specific Python SDK designed specifically for synthesizing simulation-ready articulated 3D assets9. Rather than relying on static 3D meshes, the Articraft agent generates Python scripts that programmatically define visual meshes, collision primitives, joint limits, and mass distributions9. The SDK includes automated inertia calculation routines that compute diagonal inertia matrices and center-of-mass positions directly from the generated geometric solid9. Using this framework, the Articraft-10K dataset was created, containing over 10,000 articulated objects spanning 245 categories9. These generated assets export directly to URDF format and have been validated in robotic manipulation tasks and reinforcement learning environments within NVIDIA Isaac Sim9.  
These generated URDF assets bridge the gap between AI design and physical robotics8. Once a generative framework exports a valid URDF containing rigid meshes, mass tensors, and kinematic joint limits, the asset can be loaded directly into NVIDIA Isaac Sim28. Utilizing Isaac Lab, developers define articulation configurations, set up physics properties such as joint stiffness and damping, and train locomotion or manipulation policies using reinforcement learning algorithms like Proximal Policy Optimization (PPO) and Adversarial Motion Priors (AMP)29.

A trade-off exists between direct B-Rep diffusion models and programmatic code synthesis frameworks5. Direct B-Rep models generate complex, non-analytical surfaces directly in 3D space, bypassing the restrictions of 2D sketch profiles5. However, the resulting model is static; altering a dimension requires re-running the neural diffusion process5. Programmatic CAD models generate human-readable source code defined by explicit parameters, allowing engineers to modify parameters directly within standard engineering pipelines without re-inference7.  
Programmatic generation requires sandboxed execution environments to handle syntax errors or invalid topological operations generated by language models7. Consequently, agentic frameworks rely on headless feedback loops and automated code repair to guarantee valid geometric outputs8. For physical simulation, direct B-Rep models produce only rigid boundaries without semantic joint limits or mass-density calculations5. Programmatic agentic systems excel in robotics applications by constructing complete kinematic assemblies, calculating mass-inertia matrices from solid volumes, and exporting simulation-ready URDF specifications8.

## **Conclusions and Task-Specific Recommendations**

The landscape of open-source generative AI for CAD modeling has expanded from static geometry generation to programmatic, simulation-ready robotics asset synthesis5. Based on architectural capabilities, geometric precision, execution stability, and physics integration, specific models are recommended for targeted robotics engineering tasks:  
For generating articulated robotics simulation assets and URDFs, **Articraft**9 and **ArtiCAD**8 represent the leading open-source solutions. These systems synthesize multi-part assemblies, construct semantic kinematic trees, assign physical mass properties, and export valid URDF structures ready for direct import into NVIDIA Isaac Sim or ROS environments8.  
For text-to-parametric mechanical component design, **Seek-CAD**10 and **CAD-Coder**7 provide the most robust programmatic code generation workflows. CAD-Coder offers a fine-tuned multimodal model for generating CadQuery code from image inputs7, while Seek-CAD provides an advanced reasoning framework leveraging local models to handle industrial features such as filleting, chamfering, and shelling10.  
For organic, non-analytical surface modeling and direct STEP generation, **BrepGen**18 and **DTGBrepGen**12 are optimal. These direct B-Rep diffusion models synthesize complex, freeform solids directly, making them suitable for custom robot gripper shells, aerodynamic fairings, or ergonomic end-effector surfaces where parametric sketch profiles are insufficient5.
